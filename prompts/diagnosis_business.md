# Spreadsheet task review

Review ALL assigned_check_ids using the supplied workbook, task, trajectory and executable evidence. Diagnose the task regardless of solver success. Return the exact supplied JSON schema, with every assigned assessment once and concrete evidence. Do not invent executed tests, output routes or grade solver completion.

Use the standard of a professional spreadsheet workflow: the analyst interprets the model layout, row labels, intact formulas and ordinary financial conventions. A task need not teach accounting, restate every formula, define every helper row in prose, or enumerate a solution's execution order. Missing a calculation tutorial is not missing business data. Flag a missing assumption only when a material business choice cannot reasonably be resolved from the complete public workbook and ordinary modeling conventions. Give the actual competing readings and affected output; a solver mistake alone is insufficient.

Q01: The public workbook and task must provide the necessary source data and custom business assumptions. Infer ordinary financial relationships from the workbook.
Q02: Identify material business ambiguity or contradiction, rather than demanding an explicit prose rule for every arithmetic or presentation detail.
Q03: The requested scope, actual worksheets and final output path must agree. Preserve outside formulas and literals while allowing dependent results to recalculate. Development /workspace fixtures refer to the same file mounted as /app/input.xlsx in the final task; save /app/output.xlsx there.
Q04: Assess the business validity of the full changed-value scope using the source evidence, independent calculations and public recovery. A copied golden file alone proves no financial correctness. An independently executed model and coherent statement/cash/debt reconciliations are useful evidence. Check the actual goal when private evidence needs confirmation.
Q06: The mutation or mask must have its claimed effect, preserve inputs and structure and contain no unauthorized changes. Missing caches in an agent draft are harmless because final grading recalculates it; answer caches in the delivered masked input are a leak.
For root impacts, distinguish executed single-root and marginal recalculations from a supported independence proof. A `separated_roots_with_actual_combined_LO_values` receipt proves each root changes individually and in the combined mutation only when both original and mutated complete dependency graphs exclude every root-to-root path, all formulas and caches are bound, and every root's actual combined recalculated value differs from the goal. This is an alternative proof of those effects; it does not claim individual LibreOffice executions or certify financial correctness. Reject an incomplete or failing receipt.
Q07: Look for exposed golden answers, hidden solution files, equivalent complete answer copies, or instructions that supply corrected formulas. Necessary custom policies and legitimate surviving model formulas are not automatically leaks. Excessive stepwise solution instructions should be identified with concrete examples.
Q08: Candidate review looks for an executable shortcut, not a proxy difficulty score. Cell counts, solution time and a single successful attempt do not by themselves establish difficulty. When no local hard-constraint or shortcut probe applies, return not_applicable and state that the separate frozen strongest-model cohort evaluation remains pending. Do not count this as a difficulty pass.
Q09: Inspect native errors and full changed-value dependencies. Follow the supplied deterministic native-error probe receipts and path certificates; an unsupported verbal exclusion cannot waive a contaminated required output. Sensitivity probes are not a financial correctness certificate.
Q05/Q10/Q11/Q12 and any other assigned checks: use the supplied actual control, recalculation, infrastructure and coverage evidence. State unknown when required evidence is missing. Do not demand unavailable future cohort evidence during candidate construction.

Issue objects identify problem_id, certainty, severity, claim and concrete evidence. Separate task defects, environment failures and agent errors. Preserve all assigned-check coverage, exact artifact bindings and executable verification; never manufacture a low success rate from an invalid reference or a failed environment.
