# 架构与运行契约

目标目录为干净独立仓库。输入只保证 xls/xlsx 和若干 sheet；字段、布局、语义、公式和正确性未知。正常流水线为 discover → normalize → profile → plan → construct → instruction → precheck → trajectory → diagnose → repair/freeze → export → Harbor controls。

BaseNode 统一输入输出验证、开始结束事件、耗时及异常，继承节点只承担单一阶段。RunContext 保存 run_id、配置、审计、模型和引擎服务；TaskContext 保存来源、任务版本与公开/私有产物引用。控制器统一管理题量配额、候选预算、补证和实质性修题预算。

公开和私有数据物理隔离。公开题面和画像从实际 input 重新生成；求解器不能访问 goal、修改日志或私有恢复程序。原始文件和规范化基线只读，每次修复从基线重新构造。

检查插件默认全启用，按程序/hybrid 和可见性分批。LLM 只处理 assigned_check_ids，不以完整作答或 reward 决定是否诊断。Q08 本轮按用户要求明确标记难度暂缓；Q01—Q07、Q09—Q12 正常执行。未知、失败和禁用均不等于通过。

数据集验收计数：输入清单数、被打开的独立源数、候选数、通过节点数、拒绝原因、最终合格题数分别保存。报告源转化率（有产出的源/实际尝试源）、候选转化率（合格题/候选）、每源产量（题/源），不得混用。

每次运行创建本地实时面板，预检查失败同样可见。事件写入 SQLite，JSONL/统计是可重建投影。token 使用 CLI 实际事件；费用缺少可靠价格或服务计费数据时标记未知，不以零代替。运行墙钟时间与并发节点累计耗时分别统计。

原型、生成候选、局部对照和真实 Harbor 验证分别标注；只有完成全部本轮门禁的任务进入合格目录。正式难度迭代后续采用 Codex CLI gpt-6.1-sol / xhigh 独立执行，不复用开发失败挑选统计。
