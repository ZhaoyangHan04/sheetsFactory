- 模型为原生 Codex CLI `gpt-6.1-sol` / `xhigh`，四个独立进程并行；每题独立上下文，只执行一次逻辑尝试，没有外层重试。
- 官方题面原样保留，仅追加输入和输出路径。完整原始输入及参考文件保持不变，参考文件不提供给解题者。
- 每题累计工具执行时间必须严格小于 1800 秒，排除模型响应时间，并行工具用时相加。14400 秒为运行保护时限，触发保护或计时缺失时单列待判定。

- 官方原始分数与带工具预算、资源及运行完整性条件的有效分数分别保存。实际工具超时可令有效分数为 0；运行故障、计时未知或资源证据不足不会自动算成模型错误。
- 每次运行同步启动面板，保留逐题轨迹、提交文件、原始评分、运行资源和计时证据。研究用量与生产造题转换率分开统计。

## 从失败证据到新题

逐题诊断先关联原题身份、实际轨迹、提交文件和评分差异，再区分以下情况：漏掉应修区域、错误的业务定义或期间映射、扩大修复范围、边界条件遗漏、工具预算失败，以及题意、缓存、公式文本、颜色或评分政策引起的差异。尚未证实的原因保留为假设，不归入已证明的业务能力缺陷。

每个可迁移原因必须列出具体单元格或区域、轨迹中的相关操作、公开业务政策依据及未确认部分。新题从其他合规来源构造，保留必要业务约定，扩大对应的真实依赖、不同布局、期间或边界情况；不能仅把一个原题复制、改名后当作新种子。组合多个维度时，分别保留其作用范围和独立正确答案依据。

新题准出仍需通过业务正确性、公开信息充分性、实际 oracle/nop、完整修改集合等条件。开发阶段可在实际计算与正反对照通过后先做首次最强模型测试，及时停止投入已被轻易解出的版本；这不授予正常质量或准出资格。官方复测失败不等于迁移后的新题已经有难度；新的实际成绩和最终冻结确认是独立证据。
