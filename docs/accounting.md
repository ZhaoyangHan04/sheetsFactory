# 产量、时间与费用核算

报告器只读 SQLite 审计库和实际产物，不更新任务、不补跑模型，也不改变准出结论。输出 JSON、中文 Markdown 和可离线打开的独立 HTML。

```bash
.venv312/bin/python scripts/report_run.py outputs/runs/RUN_ID \
  --engineering-dir outputs/runs/PILOT_ID \
  --billing-scope-note '凭据计费窗口包含工程与试跑重叠及未记录的取消请求，不能逐调用归因。'
```

接口为 `generate_report(run_dir, ...) -> dict` 和 `write_reports(run_dir, output_dir=None, ...) -> dict`。后者返回三个输出路径及结构化报告。

## 产量的不同分母

| 指标 | 定义 |
| --- | --- |
| 归档扫描数 | 来源清单中实际扫描的不同工作簿数；本批 EUSES 为 720 |
| 种子池数 | 经过结构筛选而选入的来源数；本批初始池为 70，续跑补充与合并后的池大小另列 |
| 预处理尝试数 | 单独的数据准备阶段尝试规范化和画像的独立来源数；本批初始为 70，续跑准备汇总为 97 |
| 可读取画像数 | 预处理成功得到可读取画像的数量；不能把尝试数当成功数 |
| 正式运行使用种子数 | 正式运行创建过候选任务的不同 source_id，包含早期拒绝 |
| 构造节点到达种子数 | 至少一题实际运行过 construct 节点的不同 source_id |
| 产题种子数 | 至少贡献一道已核验合格任务的不同 source_id |
| 候选题数 | 审计表中不同 task_id 的数量，变体分别计数 |
| 已核验合格题数 | 标记 qualified，且有合格诊断、实际 Harbor oracle/nop 和独立恢复产物证据 |

候选转化率 = 合格题数 / 候选题数。

源转化率 = 产题种子数 / 正式运行使用种子数。

每种子产题数 = 合格题数 / 正式运行使用种子数。

同一来源的 v1、v2 变体不是新的种子。两类任务也不能把同一工作簿重复算成两个来源。分母为零时显示未知，不输出虚假的 0% 或 100%。

续跑准备汇总的 97 个独立来源覆盖数据准备范围，不能当作正式运行实际使用数。实际使用数从本次运行候选任务的不同 source_id 统计；合并种子池、预处理尝试、实际到达构造节点和产题来源继续分别展示。

## 准出证据

Harbor 读取 `harbor_controls.json` 或审计中的逐题控制记录。oracle 必须实际为 1，nop 必须实际为 0，matched 为 true，且没有异常。缺控制文件不是通过。

独立恢复检查对应最终版本的 `private/independent_recovery.json`：公开信息隔离标记、程序重放成功和重算值比较成功均需存在。诊断还需有同版本的可放行报告和完整的启用检查结果。

审计标记 qualified 与证据不一致时，报告分别保留“审计标记合格”和“已核验合格”，写出一致性警告，不修改原任务。

## 时间

- 端到端经过时间使用 `timing.end_to_end_elapsed_seconds`：活跃运行从原始 `started_at` 至报告 `generated_at`，标为 `live`；终态或已停止阶段从 `started_at` 至有效 `finished_at`，标为 `known`。它包含优雅 checkpoint 与后续续跑之间的停顿。
- Producer 活跃阶段累计时间使用 `timing.active_producer_cumulative_phase_seconds`。已停止阶段使用持久化的 `run.wall_seconds`；续跑活跃阶段使用已知的 `previous_wall_seconds` 加当前 `execution_phase_started_at` 至报告时间的秒数，不含阶段间停顿。
- 两个时间指标是不同口径，不能相加。旧 `timing.wall_seconds` 与 `wall_scope` 保留给已有消费者，不再以“正式运行墙钟”作为展示标签。
- 每个新时间指标同时输出 `status` 与 `scope`。缺少启动、结束或此前阶段累计时标为 `unknown`，不猜零；中断后不把 Producer 活跃时间继续累计至报告时间。续跑时保留的上阶段 `finished_at` 不作为活跃运行的结束时间。
- 节点累计时间是所有执行尝试耗时之和，包括重试；并发时可能大于墙钟时间。
- 数据准备累计时间另列。未记录的预处理总墙钟保持未知，不从规范化、画像等节点累计耗时反推端到端经过时间。
- 报告展示时间使用 Asia/Shanghai，原始时间戳仍保留时区。

## Token

优先使用 CLI/Provider 实际返回的 input_tokens、output_tokens、cached_input_tokens 和 reasoning_output_tokens。缓存输入属于输入子集，推理输出属于输出子集，不再加入输入加输出总数。

每个字段保存已知合计、已知调用数、未知调用数和完整性标记。取消、超时或供应商未报告用量的调用不能算作零消耗。已知部分之和只是下限信息，不能在存在未知调用时称为完整总消耗。

可显式提供工程与试跑目录；这些调用按 call_id 去重，并排除正式运行中已出现的调用。工程用量独立展示，不混入正式管线用量。

## 网关账单

读取 `private/billing_start.json` 与 `private/billing_end.json`。金额计算为：

```text
USD = (结束 total_used - 开始 total_used) / quota_per_unit
```

只有币种明确为 USD、单位一致且计数单调时才计算。本环境 quota_per_unit 为 500000；这来自实际快照元信息，代码不把它当通用常量。不额外乘 usd_exchange_rate，也不把 quota 当作 token 数。

两个快照只证明整个凭据在该时间窗口的消耗。并行工程、试跑、取消请求及窗口外的正式调用都可能影响归因，故 `production_cost_usd` 始终保持未知，除非将来接入逐调用账单证据。

开始快照晚于管线启动时，报告明确指出未覆盖的秒数。可在 `private/billing_context.json` 保存 `scope_note` 和带时区的 `overlap_ended_at`；本次 UTC 12:14（北京时间 20:14）仅是已知最初一段工程/试跑重叠的结束时间，不代表此后没有共享凭据流量。当前还能观察到未归属的 6.1 模型流量，不能默认归入正式管线，也不能据此断言全部来自工程试跑。不得把该凭据窗口费用写成精确的正式运行费用。

## 诊断、修复与难度

最终问题实例、各版本诊断观测、检查执行状态和拒绝原因分别统计。多标签拒绝原因之和可能超过拒绝候选总数。重试不等于内容修订，内容修复按版本递增单独统计。

历史运行 `20261029T121133Z-7bf764` 的目标是 20 道 Financial Modeling 加 20 道 Debugging；该轮只完成质量验收，未达到后来要求的难度门禁。当前迭代的目标是至少 10+10，必须完成事先冻结题集的独立最强模型确认，Overall Pass@1 ≤ 0.2。开发测试、质量验收、正式难度确认及最终交付分别计数，不把历史 40 题或派生源表数量算作当前难度交付。

每次解题另保留累计工具执行时间及其证据完整性，阈值严格小于 1800 秒，排除模型响应时间。完整轨迹使用精确计时；受支持的未完成轨迹只能使用有执行身份和停止证据支持的保守边界。不能确定是否满足预算时保持未知，不能因单纯经过时间超时就计为模型失败。旧执行合同、旧清单和失败记录不覆盖；对原始证据的重新解析另写补充清单，并注明没有新增模型调用。

跨运行阶段汇总先固定纳入目录和截至时间，按逻辑调用身份去重，再把已完成调用的实际用量更新到同一身份；不能同时叠加审计记录、原生会话累计用量和 Harbor 的同次 `model_usage`。在途、流式中断或缺少终值的调用继续计入未知调用数，已知 token 总数仅为下界。数据构建、原始来源、派生场景、候选、已验收题目和最终确认题目分别报告分母。

## 请求日志账单

```bash
.venv312/bin/python scripts/capture_billing.py \
  --run-dir outputs/runs/RUN_ID --start 2026-10-29T12:11:33Z
```

该命令只读本地密钥和服务端账单，将原始响应保存在 run 的私有目录。重复运行按稳定请求身份合并；服务端响应中的 `id` 是显示序号，不能用于去重。

报告中的 `billing.request_log_window` 使用服务端 `created_at` 筛选消费记录，以 `quota / quota_per_usd` 计算美元。它与账户起止 `total_used` 差额是两种独立观测，不能相加。日志覆盖区间、在途请求、延迟记账和共享凭据重叠均单独标注；`production_cost_usd` 仍保持未知，避免将时间窗错误归因为精确运行费用。公开报告只导出汇总白名单，不导出请求身份或账户信息。
