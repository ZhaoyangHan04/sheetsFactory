This route is code-ready and has only pure or mocked validation. It does not
qualify the existing P01 development result or migrate its UNKNOWN timing.
No model, office, Harbor, optimizer or publication action is part of preparation.

The unused-material development entry is
`scripts/prepare_linear_capital_scaled_development_v4.py`. Its `prepare`,
`validate` and explicit `run-development` arguments match the frozen N360 entry.
It admits the original opaque N360 source and the distinct complete forty-recipe
reference view. Actual view version remains two. It retains the shared
`.scaled_development_reservations` identity and every historical selection, so
changing a path, task name or timing policy does not reset an earlier attempt.
Freeze both mode snapshots before their first calls.

The formal entry is `scripts/publish_linear_capital_scaled_v4.py`:

1. `freeze-cohort --task-sources declaration.json --output FRESH_DIRECTORY`
2. `validate-cohort --cohort FRESH_DIRECTORY/cohort_manifest.json`
3. Explicitly authorized `run-confirmation --cohort ... --output FRESH_EVALUATION`
4. `publish --cohort ... --selection ... --evaluation ...` validates only.
   Adding `--publish` copies the pending root payload. It does not qualify it.
5. Run the two exact root commands below, retain their command receipts and
   actual resource observations, then use `finalize`. Its default is read-only;
   `--write-receipt` creates a new final qualification receipt without replacing
   the historical pending dataset manifest.

Each declaration row has `task_id`, absolute `source_run`, and family
`linear_capital_scaled_FM` or `linear_capital_scaled_DBG`. Declare every task in
every selected normal directory. All must be currently qualified: filtering a
failed task is rejected. The complete cohort is exactly ten FM and ten DBG.
Its ordered source mapping, common content identity, original history, source
and view evidence, all seventeen exported files and publication recipe freeze
before the confirmation. The shared confirmation reservation is independent of
development, but each material can spend this phase only once. All reservations
survive interruptions. There is no resume/retry command.

The normal route is genuine `linear_capital_scaled_reference_review`: all twelve
checks, supported Q01–Q04, complete original task validation, actual five local
controls and actual Harbor oracle/nop resources. It requires and claims no public
solver. The sole release-layout adaptation resolves the unique completed
current-revision `private/controls/attempt_*` directory and checks its original
`compare_files` reports. Every retained failed attempt stays bound; ambiguous
multiple completed matches are rejected. All financial construction and complete
actual D remain the original admitted task.

Confirmation uses native `gpt-6.1-sol/xhigh`, the fixed factory stream-retry-eight
profile, two CPUs, 32 GiB, pinned b3 image, MAX_CONCURRENCY=2, the strict
SUM tool budget below 1,800 seconds excluding model response time, the 14,400
second operational guard and zero outer infrastructure retries. The N360 v4
budget declaration also classifies complete normal-tail lower bounds at or above
1,800 as proved failures. Exact verified over-budget trials are scored zero even
when raw verifier reward is one. Incomplete coverage or an interval that straddles
the threshold stays UNKNOWN. Parallel primitive upper bounds are summed; only
proved unique wrapper overlap gets credit. Every original timing proof is
independently recomputed at publication and finalization.

Source and verifier calculations enforce PID256. The existing Harbor agent
schema does not enforce its declared PID limit; do not infer that limit from
the profile alone. Actual role observations retain this boundary.

The copied `dataset_manifest.json` explicitly retains
`final20_qualified=False`, `final_root_controls_pending=True`. The original
whole-cohort mean must be at most .2 with no unknowns before even this pending
copy is possible. Final qualification additionally requires both commands,
executed from the repository root:

```sh
harbor run -p SpreadsheetEval -a oracle
harbor run -p SpreadsheetEval -a nop
```

A zero exit alone is insufficient. Finalization reopens each of the twenty
results per job, each configuration, complete aggregate, delivered seventeen-file
payload and exact checksum, and actual agent/verifier resource observations.
Every oracle must be one and every nop zero, with no missing, repeated, unfinished
or exceptional trial. The pinned generic root-job audit runs unchanged in a
private seventeen-file namespace. The final root README must contain both exact
commands. Root owns its pending/final status text and the actual commands.

The nop receipt substitutes `nop` in the exact argv. These are actual execution
records, never preparation flags. Their jobs and observation records must
independently pass the final audit; the example placeholders are not evidence.
The append-only final receipt is the qualification authority, binds the root
README, and retains the original pending manifest. Old development, quality and
confirmation artifacts are never overwritten.
