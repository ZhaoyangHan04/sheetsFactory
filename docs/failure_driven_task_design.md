# 业务任务设计与失败证据

本说明区分已观察结果、参考正确性与待检验的设计。公式数、工作表数、运行时间或某个旧模型的失败，均不直接构成当前最强配置的难度证据。

## 当前配置的校准

先固定银行补全和重复计入调试两题，分别执行一次原生 Codex CLI `gpt-6.1-sol` / `xhigh`。使用固定资源和严格少于 1800 秒的累计工具执行预算，模型响应时间不计入工具时间；基础设施故障不作为模型失败。不得依据结果更换公开案例或静默重试。

原题面原始字节与追加的文件路径说明分别绑定。每题先以实际 LibreOffice 检查参考兼容性，并完成 oracle=1、nop=0。实际解答先执行本项目精确值检查，再对同一提交物单独执行官方比较；二者结果分别报告。

[固定版本官方评分器](https://github.com/RUCKBReasoning/SpreadsheetBench-2/blob/a7bdc2d358e052d35a94768e1f487c0d9e9c0011/evaluation/evaluation.py) 只遍历给定答案区域，并使用其数值容差与回归阈值。本项目任务书要求完整修改集合与类型化值匹配，继续保留这一约定。仅因辅助表或展示口径造成的精确评分零分，不能描述成模型财务计算失败。

本次固定两例的实际结果为：银行补全在两种评分下均为 1；重复计入调试在两种评分下均为 0，原官方修改准确率 0.743、回归准确率 0.9706。两次均正常结束、无重试，工具累计分别约 62 秒和 190 秒。调试提交也存在新增辅助表，但原官方评分忽略附加工作表后仍为 0；具体业务错误需要结合逐格差异和实际轨迹继续归因，不能仅用结构问题解释。该结果只校准这两道公开题，不构成新题集或整个任务类别的通过率。

本次调试轨迹进一步显示：三类重复计入涉及的 15 个原始公式均已修到参考等价值，后续又修改了原 13 张表的 592 个定义，其中 528 个为公式，并引入融资、费用和估值政策调整。原题确实要求全面审计与其他改进，因此这些额外建议不能一概称为财务错误。它提供的是目标保留与政策边界的实验线索；新题应公开固定业务政策与原始假设，明确修复范围，不能借开放审计请求与隐含参考边界制造低分。

## 题面与工作簿呈现

公开请求说明业务目标、范围和提交路径。必要的自定义税务、期限、舍入、计量与分配政策保留在可读的业务规则表中。普通财务关系可由标签、期间和现有模型结构表达，不另写逐步教程。

机器友好的字段字典、完整 JSON 副本、实现路径和大量同构辅助公式，应与题面文字分别审查。它们可能显著降低实现成本，却不一定属于答案泄漏。私有提示审查只给出具体证据和待审信号，不自动把这些信号升级成缺陷或难度结论。

生成提示应遵循以下要求：

> 写一段简短的分析师工作请求，说明预期业务结果、相关期间与范围。使用工作簿中的业务名称。保留所有必要数据与自定义政策；不要重复完整实施字典、提供解题顺序、正确公式、答案值或调试根位置。只有当标签足以唯一确定补全范围并区分应保留空白时，才允许省去逐格坐标。无法确定业务口径时，应提出具体冲突并拒绝该计划。

诊断提示应遵循以下要求：

> 无论自然尝试成功与否，都检查全部启用项目。缺少计算教程本身不是缺少假设。缺陷结论需要指出完整公开材料仍无法消除的具体冲突、合理的竞争解释与受影响输出。将解题定位错误、漏修和普通计算错误记录为模型行为，不自动归为题目缺陷。检查参考正确性、公开业务信息、完整修改集合与实际运行证据，保留缺失证据和执行故障的独立状态。

数据呈现变换必须另建版本：只改显式允许的、未被财务公式引用的说明文本；保持公式、输入数值、缓存、样式与结构，并在新参考和新输入上实际重算，逐项比较非呈现单元格。旧 JSON 恢复程序不兼容时，不能继承原公开恢复或质量结论。

已经完成的两项开发实验没有达到难度目标。多实体调试题去除重复 JSON 和程序路径后，首次最强模型测试仍得到 1，工具执行 371.134196162 秒；模型从原生业务标签重建输入，再统一修复九类字段，并继续复用保留的金额辅助公式。此次对照不支持继续仅靠呈现变化扩题。40 项投资题的实际参考和全部 38,304 处值变化均正确完成；模型第一次优化求解在约 67 秒内取得最优及次优方案，其余工具时间主要用于反复尝试证书。原计时解析器因两处时钟差异保留未知，独立完整覆盖审计得到小于 736.179 秒的保守累计上界，没有重跑模型或改写历史评分。这些结果分别要求改变统一字段修复捷径，以及改善真实决策交互；40、48、56 等维数本身不构成难度证据。

新的组合调试构造保持完整原模型，以公开项目序号生成临时投资方案，注入累计承诺额度复用和利息漏计两类真实公式错误，再明确要求复核最优投资选择。构造默认关闭，不传入最优方案。应分别验证正确与错误政策下的临时及最优计划，并寻找同一公开计划发生可行性或排序变化的证据。额度复用错误在正确政策已可行的最优计划上可能没有值差，因此不能把全部物理编辑声明成独立、最终可观察的根因，也不能用选择位变化冒充公式错误。实际固定三方案工程检查已完成八次 LibreOffice 计算，补全了完整变化集合；未观察到预声明的可行性或排序耦合见证，原工程 HOLD 保留。修复公式并重新优化仍可组成合法联合任务，但不能声称已证明所设耦合。该任务另经独立开发快照首次实测，模型正常得到原始 reward=1。旧计时解析保留未知，完整覆盖的独立保守上界为 178.718841612 秒，实际资源核验通过；它没有达到难度要求，不在同一版本重采样或继续扩产。完整质量诊断、公开恢复、真实 Harbor 控制及最终确认未完成。

## 异构合同来源

新的假设业务来源将六个法律实体、24 个月和三个情景交叉配置：月付到期还本、月付等额本金、按月计提但按季度付息三种贷款，现金付息与应计利息两种税基，以及当月检查与季度滞后检查两种契约政策。承诺额度、税务批次到期、两次实际检查后的解除限制、到期月结算和闰日计息均有独立账本中的日期见证。它没有沿用公开评测原题，也不把代码复用称为原始金融数据祖源。

该来源已完成三次实际 LibreOffice 重算，每次完整检查 274,750 个物理公式和 211,968 个财务字段；两次后续稳定性比较覆盖全部 757,443 个非空单元格，类型和值差异均为零。来源清单位于 `outputs/research/heterogeneous_contracts_v2_actual_source_20261031T043000Z/source_manifest.json`。这只认证来源。原生表含完整计算支持，适合定位调试；另一个默认关闭的补全呈现计划只保留业务输入、政策与报表，删除支持计算表，并遮蔽所有声明的数字预测结果，含零值与状态，保留政策规定的不适用空白。后者必须另行实际归一化、检查完整变化集合并进行完整任务验收。

局部调试首版预声明季度付息、税基和批次到期、契约与解除限制三个机制族，保留正确的相邻异构规则。错误必须位于实际影响政策选择或金额状态的定义中，不能只改金额显示层而留下对应的正确答案。各族需有单独实际影响证据和联合修复后的完整变化集合；不把所有物理编辑自动称为彼此独立的根因。

## 参考验证与反馈成本

在来源财务验算和实际基本控制之后，可以先冻结开发快照测试明显捷径。该结果只用于决定是否继续投入候选，不代替剩余质量检查、真实 Harbor 控制或最终冻结确认。

组合选择的正确性可由一份完整、独立核验的前缀分区证明：每个剪枝条件按公开数据和精确上界复核，每个实际叶子由另一套财务实现重新计算，最优及次优必须确实出现且唯一最优成立。参考模型另以 Decimal 和 LibreOffice 验算。两套完整优化遍历并非该验证方式的必备步骤；不得把逐叶核对描述成两次独立全局搜索。

所有阶段都记录资源、时间、实际工具调用和不完整状态。先改最强模型实际利用的捷径，再决定是否扩充场景；同版本成功后不重复采样凑零分。候选和工程产物均不计入两类各十题的正式交付数量。
