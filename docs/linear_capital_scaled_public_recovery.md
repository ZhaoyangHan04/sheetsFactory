# New N360 public recovery core

`sheets_factory.workbook.linear_capital_scaled_public_recovery` provides the new
public-table parser, shared compiler, generic runtime preparation, public-only
bundle and isolated replay/witness core. It uses the new N360 specification,
Excel emitter, Decimal B financial facade and CP-SAT B model. It does not accept
the old 240-project specification or old task-admission namespace.

The parser reads only provided native workbook tables and the current public
brief. Production has 360 project rows, 60 alternative-site groups and 120
prerequisites; other supported dimensions must be explicit tiny fixtures. Raw
identity and reconstruction reports use the new kind and version 2. Existing
financial formulas and caches are not accepted as primitive financial inputs.

`prepare_public_runtime(output)` copies exact existing code and approved vendor
bytes. Its ten generic files include the new specification, financial facade,
model B and Excel adapters and all six frozen upstream kernels. Every frozen
source is checked on cold and warm validation. `prepare_public_bundle(...)`
adds only the supplied input workbook, public brief, fresh nonce, explicit
offline configuration, runner and complete inventory. It mounts no private goal,
specification JSON, coefficient matrix, construction plan or binding map.
Preparation and parsing start no financial forward, solver, spreadsheet engine,
container or model.

The existing isolated replay lifecycle retains a pinned image, offline
16 CPU / 32 GiB recovery resources, a single public bundle mount, network
disabled, full owned container IDs, normal before/after process checks and owned
cleanup. Source LO, model and verifier profiles remain 2 CPU / 32 GiB. The
offline recovery's operational allowance is separate from the unchanged model
tool budget.

The retained host witness requires a complete checked public optimum, two
source-bound actual LO receipts, the exact calculation chain, stable complete
typed values with no money quantization, immutable revision/attempt checksums,
and an actual full-D match. Programmatic recovery is not attributed to a model
attempt and claims no third independent financial ledger or second global proof.

Normal-quality integration is deliberately deferred. No reviewed N360 opaque
source/view admission provider exists yet. `_source_binding`,
`_admission_source` and the new node therefore fail explicitly before quality
execution. The witness validator cannot accept an old `_linear_admission` or
fall through to old-family recovery. The generic parser and bundle interfaces
are usable independently; this feature creates no actual recovery receipt or
quality admission.

Offline tests use tiny public workbooks, generic vendor fixtures and mocked
native/LO evidence. They exercise the unchanged replay lifecycle and cold
two-call/typed-value checks without starting any service:

```bash
.venv312/bin/python -m pytest -q tests/test_linear_capital_scaled_public_recovery.py \
  --basetemp outputs/tmp/scaled-public-recovery-tests-UNIQUE
```
