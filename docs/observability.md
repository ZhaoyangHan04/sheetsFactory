# 审计与面板

运行开始先创建审计和面板，再做密钥、引擎与种子预检查。状态、任务、节点、CLI调用和事件写入 SQLite WAL，JSON/JSONL 是可重建投影。

节点运行开始即可在 nodes 表看到 running 状态，完成后更新同一条记录。LLM 调用记录模型、reasoning、角色、阶段、耗时、Provider实际 input/cached/output/reasoning 用量；原始输出仅在私有调用目录。失败且缺用量时保持 null。

实时面板使用 SSE，按事件ID断线续传。页面使用固定静态资源，不依赖CDN，不提供任意文件读取。历史查看器使用 mode=ro 和 query_only 打开 SQLite，能够显示仍运行任务的活跃调用，不修改 run 状态。

运行墙钟时间、节点累计时间和CLI耗时是不同指标。并发时累计耗时可大于墙钟。正在运行的调用没有最终token值时只能显示待返回，不能声称已知精确费用。

报告必须区分：扫描的原始文件、选取的种子、实际预处理来源、实际构造来源、候选任务、有产出来源、最终合格题。当前目标为20+20，达到本地ready不等于完成真实Harbor准出。
