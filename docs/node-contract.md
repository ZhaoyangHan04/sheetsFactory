# 节点、上下文和模板

BaseNode.run 负责开始/结束事件、节点运行中记录、实际单调时钟耗时、成功/失败审计；继承类只实现 execute(context)。TaskContext 使用 source、mode、revision 和产物引用传递数据，save 支持公开/私有存储；不把上游全部会话传给下游。

BasePipeline 从 config/nodes.yaml 加载 BaseNode 子类，从模式 YAML 加载 preparation、revision、evidence、infrastructure_retry、repair、export 阶段；启动时验证必需阶段、节点注册、继承关系和质量顺序。修复循环只有 FactoryPipeline 控制器能推进，节点不能自己增加题量或重置预算。

正常顺序：规范化 → 画像 → 计划 → 物化 → 题面 → 本地控制 → 独立恢复 → 自然尝试 → 全项诊断。构造不可执行时保存程序失败证据，不强迫 agent 操作损坏输入。

R11 在同一版本重试基础设施；R12 在同一版本补恢复/诊断证据；仅确认的 repair 路线进入新内容版本。max_steps、补证与基础设施预算分别计数。修复包必须引用所有被分配的问题实例；未变化的修复直接终止，避免空转。

原始源与基线不覆盖。明确的假设场景只允许改数值/空白输入，公开每个场景及单位，重算完整场景 goal 后再挖空/注错。修复不使用 solver 输出作为参考。目标闭包逐层检查错误、支持范围和真实跨表边；所有目标全零的原始模板不能直接准出。

变体维持相同 source_id，用不同 task_id 记录不同模块。相同模式的目标集合在源内比较重叠；仅改数字或换名字不算不同模块。准备、候选与最终合格题的分母独立记录。
